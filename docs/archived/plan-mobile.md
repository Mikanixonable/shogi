# モバイル対応の不足点と改善案

調査日: 2026-10-25（dev ブランチ 086638f 時点）

調査方法: Playwright で 390×844・360×740（縦）、844×390（横）を `isMobile` / `hasTouch` で描画し、
スクリーンショット・要素の矩形・タップ後のスクロール位置を実測した。

---

## A. 表示の崩れ（バグ）

### A1. 左ドックの「自分／相手」の駒（バインダー）が他の要素に重なる

- 現象: 「＋相手」が「自分」の見出しに被り、「自分 先手▲」の駒が約 180px 下にずれて、
  囲い/戦法タブと並べ方ボタンを隠す。盤とドックの間の約 75px の空白も同じ原因。
- 原因: [dock.css](../../css/dock.css) の `.dk-pc[data-who="opp"] { top:30px }` と
  `.dk-pc[data-who="me"] { top:calc(30px + min(150px,28vh)) }` のほうが、狭幅ブロックの
  `.dk-pc { top:auto }` より詳細度が高く、狭幅でも効き続ける（`position:relative` なので見た目だけずれる）。
- 修正案: 狭幅ブロックに `.dk-pc[data-who] { top:auto; }` を追加する。

### A2. 横向き（844×390）で盤が画面の約 2 倍の高さになる

- 現象: 盤が 754×804px になり、全体を一度に見られない。
- 原因: [board.css](../../css/board.css) と [layout.css](../../css/layout.css) の `@media (max-width:979px)` が幅だけで判定しており、
  盤の幅を `100cqw` で決めている。
- 修正案（どちらか）:
  - 盤の幅に高さの上限を入れる:
    `width:min(calc(100cqw - 44px), calc((100svh - ヘッダー高 - 座標) * 9 / 9.6))`
  - `(orientation:landscape) and (max-height:500px)` では「盤が左・ドックが右」の 2 列にする。

### A3. 制約バーのチップが右端で切れ、続きがあると分からない

- 現象: 「戦法 居飛車（2筋）」が半分しか見えない。
- 原因: 横スクロール自体はできるが、[constraint.css](../../css/constraint.css) の狭幅ブロックで
  `mask-image:none` にしているため、フェードによる「続きあり」の手がかりが消えている。
- 修正案:
  - フェードを戻し、`scroll-snap` を付ける。
  - 狭幅では種類ラベルの「既定」を 2 段で出さず、角の点線の印だけにしてチップの幅を詰める。

## B. 操作の流れ

### B1. 選んだ結果が画面に映らない（最重要）

- 現象: 縦に「盤 → 選ぶ（y≈540〜2335）→ 読む（y≈2335〜）」と並ぶため、囲いのカードをタップしても
  盤は画面外（boardTop −501px）にあり、変化が見えない。解説はさらに約 2000px 下にある。
- 改善案（推奨）: 狭幅では盤を `position:sticky; top:ヘッダー高` で上に固定し、高さを約 45svh に縮める。
  下半分は「選ぶ／読む」を切り替えるボトムシートにする。これで選ぶ操作と盤の変化が同じ画面に収まる。
- 軽い代替案: タップ後に「盤を見る ↑」のトーストを出す。

### B2. チップをタップすると盤が逃げ、しかも解説には着かない

- 現象: 盤上のチップをタップすると、ページが 335px 下へスクロールする（実測）。
  盤は上へ流れるが、解説は 2000px 下のまま。
- 原因:
  - [dock-view.js](../../js/ui/dock-view.js) の `reveal()` が `scrollIntoView` を呼び、狭幅ではドックが
    `overflow:visible` なのでページ全体がスクロールする。
  - [constraint-mode.js](../../js/modes/constraint-mode.js) の `_openDrawer` は 980–1180px でしか働かない。
- 修正案: 狭幅では `reveal` を止め、代わりに解説を開く（B1 のボトムシート、またはドロワー）。

### B3. ホバー前提の機能がタッチで働かない／表示が残る

- `mouseover` に頼っている箇所:
  - [board-detail-view.js](../../js/ui/board-detail-view.js): `data-sq` の項目で盤のマスを光らせる（「点線の項目は盤上に表示」）
  - [dock-view.js](../../js/ui/dock-view.js): 候補のプレビュー
  - [cites.js](../../js/ui/cites.js): 本文の [n] と出典行の連動
- CSS の `:hover` は 34 箇所あり、`@media (hover:hover)` で囲ったものがない。
  iOS ではタップ後にカードが浮いたまま（`translateY`）になる。
- 修正案:
  - `data-sq` はタップで切り替える（B1 で盤が sticky なら、光ったマスがそのまま見える）。
  - ホバー装飾は `@media (hover:hover)` で囲う。

### B4. `title` でしか説明していない操作がある

- 対象: 並べ方ボタン（▦⑂★↑↔）、「盤をリセット」の説明、系統の注記。タッチでは読めない。
- 修正案: 並べ方ボタンの横に、選択中の並べ方の名前を文字で出す。

## C. タップ領域・文字の大きさ

### C1. 44px 未満のタップ領域が約 45 個ある

| 要素 | 実寸 |
|---|---|
| 歯車 `#toolsToggle`・テーマ切替 `#themeToggle` | 28×28 |
| 凡例 `.dk-legend`（?） | 18×18 |
| チップの解除 `.cchip-x` | 22×22 |
| 相手の解除 `.dk-pc-x` | 22×22 |
| 並べ方 `.dk-sort-seg button` | 30×28 |
| 戦型の切替 `.dk-strategy button` | 高さ 29 |
| 系統見出し `.dk-fam-h` | 高さ 26 |
| 出典番号 `sup.cite a` | 13×15 |

修正案:
- 狭幅では `.ib` を 40×40 にする。
- 小さな × や ? は `::after { content:""; position:absolute; inset:-10px }` で、見た目を変えずに当たり判定だけ広げる。

### C2. 戦法タブのタイルがつぶれる

- 現象: 9 筋のグリッドでタイルが約 31px 幅になり、名前が 8px まで縮んで「矢中…」と省略される。
  派生タイル（「7六飛型」「原始棒銀」など）は 1 文字ずつ改行して縦に並ぶ。
- 修正案: 狭幅では 9 列グリッドをやめ、系統ごとに「筋の番号＋名前」の横長行のリストにする
  （囲いの発展ツリーの `.dk-row` の形を流用できる）。

### C3. 10px 未満の文字

`.dk-var .dk-vs` 7.5px、`.dk-tile .nm` 最小 8px、`.dk-seal` 8.5px、出典番号 約 9.4px。
狭幅では最低 11px を目安にする。

## D. ヘッダー・その他

### D1. ヘッダーが折り返し、画面の 13% を占める

- 現象: 360 幅では「将棋の囲い図/鑑」「このサイトについ/て」が折り返し、固定ヘッダーの高さが 97px。
  390 幅でもアイコンが 2 行目に落ちて 82px。
- 修正案: 狭幅では h1 の `letter-spacing` を詰め、「このサイトについて」を歯車のポップオーバーの中へ移すか
  「?」アイコンにして、`flex-wrap:nowrap` で 1 行 48px にする。

### D2. 相手を表示したときの 1 画面目

- 現象: 1 画面目の約 40% を 2 段の制約バーと関係ラベルが占め、360×740 では盤の下側が画面外に出る。
- 修正案: 狭幅では相手の帯を「△ 居飛車・矢倉・2筋」の 1 行要約にし、タップで展開する。

### D3. ノッチ・セーフエリアに対応していない

- viewport の meta に `viewport-fit=cover` がなく、`env(safe-area-inset-*)` も使っていない。
- 横向きのとき、ノッチ側の持ち駒列や座標が隠れる恐れがある。

### D4. テストの範囲

- [ui-check.js](../../tools/ui-check.js) は 390 の縦しか見ていないため、A1〜A3 を検出できない。
- 追加案: 360 縦・844×390 横の幅を加え、次を検査する。
  - 要素の重なり（バインダーの駒と一覧の見出しなど）
  - 盤が画面の高さに収まるか
  - タップ領域が 44px 以上か
