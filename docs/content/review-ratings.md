## 1. ratings の使われ方（なぜ整合が必要か）

囲いの ratings は表示だけでなく、並べ替えと相性スコアにも使われる。系統をまたいで同じ物差しで付けないと、画面の序列が崩れる。

| 用途 | 場所 | 中身 | 整合が効く点 |
|---|---|---|---|
| ペンタグラム | `js/ui/detail-sections.js` の `RATINGS` | 5軸を頂点に描く。軸名は hard=堅さ / wide=玉の広さ / top=上部の強さ / side=横の強さ / quick=組みやすさ。見出しのヒントは「横の強さは横からの飛車攻めへの耐性。端からの攻めは含みません」 | 軸の定義がヒント文1行しかない |
| 左ドックの並べ替え | `js/ui/dock-grids.js` の `CASTLE_SORTS` | 堅さ順・上部順・横順（wide と quick は除外）。値5→1のブロックに分け、同じ値は同じブロックに並ぶ | 系統が違う囲いが同じブロックに並ぶので、系統をまたぐ序列が見える |
| 対戦相性 | `js/core/matchup.js` の `fitness()` | スコア = Σ（戦型の重み × 囲いの ratings）。端攻め（`attacks` に `id:'hashi'`）を持つ囲いは、端攻めの前兆があると −0.5 | 値が1ずれるとスコアが重み分（0.10〜0.40）動く |
| 手数の注意 | `js/core/compat.js`（TEMPO） | `quick <= 2` の囲いと `pace:'rapid'` の戦法を合わせると「間に合いにくい」と注記 | quick の 2 と 3 の境目に実害がある |
| 戦法のペンタグラム | 同 `TACTIC_RATINGS` | attack=攻撃力 / speed=速さ / flex=柔軟性 / safety=玉の安全 / easy=覚えやすさ。ヒントは「速さは仕掛けまでの手数、覚えやすさは定跡の量と注意点の少なさ」。派生戦法は親の形を破線で重ねる | 親子で値がそろっていないと差分表示が意味を失う |

戦型ごとの重み（`matchup.js` の `BASE_WEIGHTS`）:

| 戦型 | top | side | hard | wide | quick |
|---|---|---|---|---|---|
| 相居飛車 | .35 | .10 | .25 | .15 | .15 |
| 対抗形・自分が居飛車 | .10 | .35 | .30 | .10 | .15 |
| 対抗形・自分が振り飛車 | .20 | .30 | .25 | .10 | .15 |
| 相振り飛車 | .40 | .15 | .20 | .15 | .10 |

補正: 相手が急戦なら quick と side に +.1、持久戦なら hard と top に +.1、玉と相手飛車の距離が2筋以内なら top に +.1、4筋以上なら side に +.1。

ここから導く原則:

1. 軸ごとに系統をまたぐ共通の物差しが要る（左ドックのブロックと相性スコアのため）。
2. 同じ形（左右反転を含む）は同じ値にする（本節の機械チェックで検出できる）。
3. `quick` の 2 と 3 は閾値。ここだけは手数の根拠を厳しく見る。
4. `side` は端攻めを含めない。端攻めは `attacks` の `hashi` で別に扱うので、`side` を端の弱さで下げない。

## 3. 機械チェックによる不整合の洗い出し

囲いのデータ（core・from・ratings）から、次の7つを機械的に調べた。スクリプトはスクラッチパッドにあり、リポジトリには入れていない（§7-5 に `tools/validate-castles.js` への警告追加案を書いた）。判定の列の「→ A1」などは §5 の修正案の番号。

### 3-1. 検査の一覧と結果

| 検査 | 内容 | 結果 |
|---|---|---|
| R1 | 左右反転（筋 f→10−f）または同一で core が一致する囲いの組 | 10組。不整合は6組（同じ囲いが複数の組に出るため、A1・A2・A3・A4 の4件にまとまる）、理由ありの差1組、据え置き1組、差なし2組 |
| R2〜R4 | `from` の親子で、子の quick が親より高い／強みの軸が1つも上がらない／1軸で2以上下がる | 23件が該当。不整合として残るのは4件（`ginyagura`=B5、`kakuyagura`=B7、`chonmagemino`=A4、`nagareyagura`=C1）。残りは理由が説明できる |
| R5 | 系統内の軸のレンジ | 雁木型の hard が全件2（C2）、穴熊型の wide が 1〜4（A1）、簡易囲い型の wide に 5 が1件（C3） |
| R6 | 根拠のない極端値（5 と 1） | 根拠が見つからない 5 は 2件（ryusenyagura の hard、ahiru の wide）。top=5 の gangi は引用が根拠を示していない |
| R7 | quick と手数の概算の相関 | r = −0.85（n=85）。外れ値は millennium（B6）と kinmusou（B3） |
| R8 | hard と（top, side の平均）の相関 | r = 0.83（n=86）。外れ値は kakuyagura（B7）と gangi（C2）。hirame・tsunogin は理由あり |
| R9 | 盤上の駒として到達できない配置（角の色、桂の跳び、香の筋） | `kakuyagura` の `角67` が到達不能（ratings とは別件。3-5 に記す） |

手数の概算（R7）の作り方: core の駒ごとに、初期位置から1手ずつ動かしたときの最短手数を求めて合計する（駒の移動は玉・金・銀の動きで幅優先探索、桂・香は前進のみ、盤上の他の駒は無視。金・銀・桂・香は2枚の初期位置への割り当てが最小になる組を採る）。歩の突き出し（shell の歩が7段より上にあるぶん）は別に数え、quick の比較には core の手数だけを使った。

### 3-5. ratings 以外で見つかったこと（担当外だが伝えておく）

### 4-4. 外部の目安: shougi.jp の星評価との比較

**何を見たか**: shougi.jp「将棋の囲い」の囲い52ページ（一覧 https://www.shougi.jp/kakoi/ ）には、各ページに「組みやすさ・堅さ・攻撃力・発展性・初心者おすすめ度」の星5段階の表がある。注記は「※評価は当サイト独自の目安です」で、各項目の定義は書かれていない（雁木囲いのページを WebFetch で確認し、残りは同じ表を HTML から読み取った）。このうちアプリの囲い50件に対応づけられた。

**軸の定義の違い（必ず守ること）**:

| 点 | shougi.jp | このアプリ | 注意 |
