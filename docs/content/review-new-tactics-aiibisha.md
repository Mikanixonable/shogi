## 3. 戦型の総称を戦法として持つことについての横断提案

9件のうち `yagura-senpou`・`aigakari`・`kakugawari`・`yokofudori` は個別戦法ではなく戦型（senkei）の総称で、`senkei` フィールドに同名の戦型 id を持つ二重登録になっている。現状の設計（`basic: true` の代表配置＋`desc` で「戦型」と明記＋`senkei` リンク）は機能しており、データ上の不整合も見つからなかった。一方で、以下の点は今後の検討課題として残す。

- `aigakari` の lead は飛28（飛車が動かない）で、`lead.square` を表示する UI 上では「主役の駒」として意味を持たない。戦型総称エントリでは lead を「分類上の親」として扱う運用に倒すか、表示側で basic エントリの lead を弱める検討余地がある
- 総称エントリの `pieces` は「代表配置」にすぎず、レビューでも Wikipedia の代表図と必ずしも一致しない選択がなされていた（相掛かりの現代型/旧型、横歩取りの△2三歩分岐）。`note` や `desc` に「どの手順系の配置か」を明記する運用を推奨
- 駒数モデル（先手＝1組9枚）の制約で、駒が多く取られた局面は表せない。横歩取りの主線形（盤上7枚＋持ち歩3枚）は表現不能で、△2三歩分岐の形で代用するしかなかった。大駒交換の激しい戦型では今後も同様の制約が出る可能性がある
- `itteson-kakugawari`・`aonoryu`・`yuukiryu` のように `variantOf` で親と同系の pieces を持つ設計では、親の pieces を直すと派生も連動する。今回の歩87の検討が3件連動していたように、派生戦法の pieces は親修正の影響を定期チェックするのが安全
