## 3. 横断提案

### 3-1. 出典トークンと本文の照合を、追加の手順に入れる
- 7件中6件で、`[[ref]]` が指す記事に書かれていない主張が付いていた。バリデータは「宣言済みか・登録済みか」しか見ないので、これは検出できない
- 提案: データを足すときに、主張ごとに「出典のどの文から取ったか」を1行で控える（レビュー文書の検証表と同じ形式）。控えが書けない主張は、トークンを付けず「（推測）」として desc から外すか、別の出典を探す
- 今回よくあった型: ①別の記事（wj-yagura）にある記述を wj-yonenaga のトークンで引いた、②**docs/content/coverage-tactics.md §3 の案文がそのまま desc/pros/cons に入り、案文自体に誤りや根拠のない文があった**（「史上最初の対振り飛車戦法」「藤井聡太が…採用」「左銀を▲6八銀〜5七銀〜4六銀と中央へ」「定跡の蓄積が浅い」「歩切れと形の歪み」「相掛かり定跡の外で戦える奇襲性」）、③主客の取り違え（村田システム）
- 計画書の案文は出典の裏づけを取る前の下書きなので、実装するときは主張ごとに原文を確かめ直す

### 3-2. note の「要検証」を【要確認】に統一し、図の由来は「図は〇〇の図」と書く
- 6件の note が「要検証」「組み立てた図」だった。バリデータが警告に出すのは `【要確認】` を含む note だけなので、これらは警告にならず放置されていた
- 提案: 未確認の印は【要確認】に統一する。確認できたら「図は Wikipedia『〇〇』の基本図（▲□□まで）」のように由来を書く。今回の7件は、すべて由来を確定できた（Wikipedia の図か、日本将棋連盟コラムの手順から再現した図）
- 文献に代表局面の図が無い戦法（中田功XP）は、「連盟コラムの第1図に▲1六歩を足した形」のように、**どこを足したか**まで書く

### 3-3. `variantOf` は派生関係の表現。セルを共有するための手段にしない
- `yonenaga-kyusen` は、4六のセルに入れるために早繰り銀の派生にされていた（coverage-tactics.md の案が根拠なしに実装された形）。米長流の文献は、銀57と桂37を骨子にしており、早繰り銀（右銀を37→46）とは別系統
- 提案: lead.square は文献の図から決め、親がいないものは `variantOf` を付けない。関係（嬉野流の派生形とされる村田システム、塚田スペシャルの構想を受け継ぐひねり飛車、雁木の対振り引き角を受け継ぐ飯島流引き角）は desc・note に書く。村田システムと嬉野流は lead.square が違うので `variantOf` にできない

### 3-4. 後手番発祥の戦法の書式を統一する
- 現状: `pacman-44fu` は note で「後手番の局面を先手視点に180度反転して表示」と断る。`itteson-kakugawari` は desc で断る。`yonenaga-kyusen` は note に「後手番発祥のため先手版の図は要検証」とあるだけ
- 提案: tags に `'後手番'` を付け、note は「後手番の局面を先手視点に180度反転して表示。図は〇〇の反転」に揃える。先手番で使われる現代形がある場合（米長流の「▲5七銀まで」図）は、別形として note に併記する

### 3-5. 廃れた戦法・歴史的戦法であることを見せる

### 3-8. pairings の ok が、相性判定では ng になることがある
- バリデータは pairings の「形式」（囲いの存在・出典・◎の衝突）しか見ない。実際の組み合わせ可否は `Kakoi.compat.judge` が決める。今回の7件の既存 pairings のうち、判定が ng になっていたのは `nakata-xp × mino` の1件（essential の玉39が固定されて、美濃の玉28を置けない）
