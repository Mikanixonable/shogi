# 実装計画：戦法の閲覧モードと、囲いの形による分類

将棋の囲い図鑑（`shogi/castles.html`）に、次の2つを加える計画。

1. **戦法の閲覧モード**：「どの筋に主役の駒を置く戦法か」を周期表のように並べて見せる
2. **囲いの分類**：囲いを形の系統（舟囲い型・矢倉型・雁木型 など）でまとめ、形の近さも可視化する

もとになった着想（作者の投稿）：

> 振り飛車で使われる二段ロケット、向かい飛車、三間飛車、四間飛車、中飛車はそれぞれ9筋（or1筋）、8筋、7筋、6筋、5筋に飛車を置く戦法であり、居飛車で使われる棒銀、早繰り銀、腰掛け銀はそれぞれ2筋、3, 4筋、5筋に銀を置く戦法だ。なんだか周期表的で美しい

> 居飛車の囲いは大きく分けて船囲い型、矢倉型、雁木型に大別できそう。船囲いには7九金型、6八金型がある。形はだいぶ違う。矢倉型は逆L字形をしている。雁木型は銀が出ている逆V字型だが、並列するとカニ囲い、左前に銀がいると兜矢倉と呼ばれる

## 1. 目指す体験

### 1-1. 戦法モード：「筋」でそろう周期表

- 盤の筋（９〜１）と**列をそろえた表**を、盤の真上に置く。表の列と盤の列が一致しているので、「表のこの列＝盤のこの筋」がひと目で分かる。
- 行は「主役の駒」ごとに分ける。

  | 行 | ９筋 | ８筋 | ７筋 | ６筋 | ５筋 | ４筋 | ３筋 | ２筋 | １筋 |
  |---|---|---|---|---|---|---|---|---|---|
  | 振り飛車：**飛車**の筋 | 九間飛車 ※1 | 向かい飛車 | 三間飛車 | 四間飛車 | 中飛車 | | | | （一間飛車）※1 |
  | 居飛車：**銀**の筋 | | | | | 腰掛け銀 | 早繰り銀 | 早繰り銀 | 棒銀 | |
  | 居飛車：**飛車**の筋（発展） | | | | | 中飛車（居飛車） | 右四間飛車 | 袖飛車 | 居飛車 | |

  ※1 投稿では9筋を「二段ロケット」としているが、調べた範囲では、二段ロケットは「飛車と香などを同じ筋に縦に重ねる攻め方」を指す呼び名としても使われている。9筋・1筋の振り飛車の正式な呼び名（九間飛車・端飛車など）と合わせて、**フェーズ1で出典を確認**する（未確定事項 Q1）。

- 表のマスを選ぶと、盤の主役の駒が**その筋へ滑るように移動**する（今の駒移動の演出を再利用）。
  - 振り飛車の行を左右に動かすと、飛車が８→７→６→５筋と隣へ移っていき、周期表を横にたどる感覚になる。
  - 「順に再生」ボタンで、端から端まで自動でたどる。
- 主役の駒は朱色で強調し、その戦法でよく組まれる囲い（例：四間飛車＋美濃）を薄く表示する。
- 主役の駒の**移動経路**を矢印で示す。
  - 例：棒銀は ▲3九銀→3八→2七→2六
  - 例：腰掛け銀は ▲3九銀→4八→5七→5六
  - 経路はフェーズ1で出典を確認する。
- 解説欄は「概要／組み方／相性のよい囲い／出典」の4タブにする。「相性のよい囲い」を押すと、囲いモードのその囲いへ移る。

### 1-2. 分類：形でまとまる囲い

作者の分類を「**形の系統**」として正式なデータにし、一覧・盤・地図の3か所で一貫して見せる。

| 系統 | 形の特徴 | 所属（今のデータ） | 細分類 |
|---|---|---|---|
| **舟囲い型** | 玉が7八、金銀が玉の横から下に広がる | 舟囲い（7九銀型）、舟囲い（6八銀型）、エルモ囲い、舟囲い（6八金型） | **7九金型**（エルモ）／**6八金型**（6八金型）。基本形の扱いは未確定事項 Q2 |
| **矢倉型** | **逆L字**：玉の右上を金銀が囲む | 金矢倉、ボナンザ囲い（片矢倉系） | 金矢倉／片矢倉系 |
| **雁木型** | **逆V字**：銀が前へ出る | 雁木（旧型）、ツノ銀雁木、**カニ囲い**、**兜矢倉** | 二枚銀／ツノ銀／**並列＝カニ囲い**／**左前に銀＝兜矢倉** |
| 穴熊型（追加案） | 隅にもぐる | 居飛車穴熊、振り飛車穴熊 | — |
| 美濃型（追加案） | 斜めの連結 | 左美濃、本美濃、片美濃、高美濃、銀冠、ダイヤモンド美濃 | 片美濃→本美濃→高美濃→銀冠 |

- **名前と形の食い違いを見せる**：兜「矢倉」は名前は矢倉系だが、形は雁木型。こうした「名前の系統」と「形の系統」のずれを、カードの小さなバッジ（例：「名前は矢倉系」）で示す。
- **一覧（左）**：カードを系統ごとに見出し付きで並べ、系統のチップで絞り込めるようにする。カードには系統の形を表す小さな記号（逆L・逆V など）を添える。
- **盤（中央）**：系統の「骨格」（玉と金銀を結ぶ線）を盤上に薄く線で描くスイッチを付ける。逆L字・逆V字が実際の形として見える。
- **分類マップ（新しい表示）**：囲いの形の近さを2次元に並べた地図。
  - 近い囲いほど近くに置く。
  - 色は作者の分類、位置は計算による形の近さ。手作業の分類と計算結果がどこで一致し、どこでずれるかを見比べられる。

### 1-3. 画面の役割（今の設計原則を保つ）

- ヘッダーの左端、タイトルの隣に、アプリ全体の**表示の切り替え**「囲い／戦法／分類マップ」を置く。
  - これは「何を見るか」を選ぶ最上位の操作なので、表示設定（右側）とは分けて置く。
- 左＝選ぶ、中央＝見る、右＝読む、の3分割はどの表示でも保つ。
  - **戦法**：左に周期表の縮小版、中央に周期表＋盤、右に戦法の解説
  - **分類マップ**：左に系統のリスト、中央に地図（点を押すと盤のミニプレビュー）、右に系統の解説

## 2. データ設計

### 2-1. 戦法 `js/data/tactics.js`（新規）

```js
Kakoi.TACTICS.push({
  id: 'shikenbisha', name: '四間飛車', reading: 'しけんびしゃ',
  family: 'furibisha-rook',      // 周期表の行
  lead: { piece: '飛', file: 6 }, // 主役の駒と筋（表の列）
  pieces: '…',                    // 主役まわりの駒（先手のみ、setup と同じ表記）
  route: ['28', '68'],            // 主役の駒の移動経路（矢印）
  castles: ['mino', 'takamino'],  // 相性のよい囲い（CASTLES の id）
  desc: '…', sources: [{ ref, for }],
});
```

- `family` は表の行定義 `Kakoi.TACTIC_FAMILIES` を参照する（例：`furibisha-rook`＝振り飛車の飛車の筋、`ibisha-silver`＝居飛車の銀の筋）。
- 早繰り銀のように**複数の筋にまたがる**戦法は `lead.file: [4, 3]` とし、表では2マスにまたがって表示する。

### 2-2. 系統 `js/data/taxonomy.js`（新規）

```js
Kakoi.FAMILIES = [
  { id: 'funa',   name: '舟囲い型', shape: '玉の横から下へ広がる', glyph: 'funa',   subtypes: [{ id: 'kin79', name: '7九金型' }, { id: 'kin68', name: '6八金型' }] },
  { id: 'yagura', name: '矢倉型',   shape: '逆L字',               glyph: 'L' },
  { id: 'gangi',  name: '雁木型',   shape: '逆V字（銀が前に出る）', glyph: 'V', subtypes: [{ id: 'heiretsu', name: '並列（カニ囲い）' }, { id: 'hidarimae', name: '左前に銀（兜矢倉）' }] },
  // 穴熊型・美濃型は Q3 の回答しだい
];
```

- 各囲いには `family`（系統）・`subtype`（細分類）・`nameFamily`（名前の系統。形の系統と食い違うときだけ）を持たせる。
- 今の `group` は表示用の分類なので、`family` に置き換えて一本化する。

### 2-3. 形の近さの計算 `js/core/shape.js`（新規・副作用なしの関数のみ）

1. **形の特徴量**：囲いの駒（金銀と、穴熊などでは桂香も）について、**玉からの相対位置**を集める。振り飛車の囲いは左右反転して居飛車側にそろえる。
2. **2つの囲いの距離**：駒の種類ごとに、相対位置どうしを最も近くなるように対応づけ、その移動距離の合計を距離とする。
   - 駒が足りない分は一定の値を加える。
   - 駒は最大4枚程度なので、総当たりで計算できる。
3. **クラスタリング**：上の距離で、近いものから順にまとめていく（階層的クラスタリング）。結果は木の図（デンドログラム）で表示できる。
4. **地図の座標**：距離の表から、各囲いの2次元の位置を計算する（古典的多次元尺度構成法。18〜30点なので軽い）。
5. どれも引数だけで結果が決まる関数にし、Node から検証スクリプトで試験する。

## 4. 進め方（フェーズ）

依存関係のない作業は並列のサブエージェントに任せる。データ入力や機械的な変更は Sonnet が担当し、設計判断と最終確認は Opus が行う。

### フェーズ0：土台の整理（前提）

新しいデータの種類が増える前に、リファクタリング候補の高1〜3を済ませる。

- 0-a `js/core/validate.js` に検証を一本化（Sonnet）
- 0-b `js/manifest.js` を作り、HTMLと検証スクリプトで共有（Sonnet）
- 0-c `js/core/repository.js` を作り、ビューが `Kakoi.*` を直接読まないようにする（Opus が設計、Sonnet が置き換え）

0-a と 0-b は並列に進められる。0-c は 0-a の後に行う。

### フェーズ1：調べもの（フェーズ0と並列）

- 1-a 戦法の主役の駒・筋・移動経路・相性のよい囲いを、1戦法あたり2件以上の出典で確認する（Sonnet・振り飛車／居飛車で2並列）
- 1-b Q1（9筋・1筋の飛車の呼び名と「二段ロケット」の意味）の出典確認（Sonnet）
- 1-c 系統の名前（「舟囲い型」「矢倉型」「雁木型」「逆L字」「逆V字」など）に一般的な用法があるかの確認（Sonnet）

### フェーズ2：分類（データ→計算→表示）

- 2-a `taxonomy.js` と各囲いの `family`・`subtype` を入力し、`group` を置き換える（Sonnet）
- 2-b `shape.js` の実装と Node での試験。手作業の分類と、計算で得たクラスタがどれだけ一致するかを出力する（Opus）
- 2-c 一覧の系統見出し・絞り込み・バッジ（Sonnet）
- 2-d 盤上の骨格線（Opus：見せ方、Sonnet：実装）
- 2-e 分類マップ（Opus）

2-a と 2-b は並列に進められる。2-c と 2-d は 2-a の後、2-e は 2-b の後に行う。

### フェーズ3：戦法モード

- 3-a `tactics.js` の入力（1-a の結果から、Sonnet）
- 3-b 表示の切り替えと状態の追加（Opus）
- 3-c 周期表の表示と、盤との列合わせ（Opus）
- 3-d 移動経路の矢印・順に再生（Sonnet）
- 3-e 解説欄のタブ構成と、囲いモードへの行き来（Sonnet）

3-a は 3-b・3-c と並列に進められる。

### フェーズ4：確認

- ブラウザで、全戦法・全囲いをPlaywrightで巡回する。エラー・はみ出し・幅980px以上でのスクロールの有無を確認する（Sonnet）
- 画面幅 1440／1280／1100／1024／390 とライト・ダークのスクリーンショットを撮り、目で確認する（Opus）
- `node shogi/tools/validate-castles.js` がすべて通ること

各フェーズの終わりにコミットする。
