## 1. 表示崩れ・揺れ

### F1/F2：盤の大きさが状態によって変わる（根本原因は1つ）

**現象**（f6904a4、明るいテーマ、3D）

| 幅 | 初期 | 相手の戦法を選ぶ | 相手の戦法チップを選ぶ |
|---|---|---|---|
| 1440 | 413×440 | 310×331 | 181×193 |
| 1280 | 354×377 | 128×136 | 31×33 |
| 1100 / 1024 | 287 / 246 | **0×0** | 0×0 |

- 相手を加える、戦略を切り替える、左ドックの系統を折りたたむ（!）、トーストが出る、といった操作のたびに、盤の位置と大きさが変わる。

**原因**

- `.boardarea` は `container-type:size` で、盤の高さは「中央の残りの高さ」から決まる（`css/board.css:5-6`）。
- 盤と同じ列に、高さが状態によって変わる部品が積まれている。
  - 相手の帯、自分の帯：補足文が折り返す（`layout.css:112,118-121`）
  - 制約バー：`flex-wrap`（`constraint.css:5`）
  - 周期表：行数によって96〜158px
  - `.stage-f`：20/41/61px
  - トースト：通常のフローの中に入る（`matchup.css:76`）
- さらに 1280px 以下ではヘッダが2行になり、高さが 54 から 96px になる。

**方針：盤の大きさは「画面の大きさ」だけで決め、状態には依存させない**

1. **中央を固定の行にする**。各行の高さは定数とし、中身がはみ出したら省略・横スクロールにする。

   ```
   .stage { grid-template-rows: var(--band-h) var(--pt-h) minmax(0,1fr) var(--band-h) var(--foot-h); }
   ```

   - 帯は `--band-h:56px` 固定。見出し1行と制約チップ1行で構成する。チップは折り返さず横スクロールし、端をフェードさせる。補足文は1行で省略し、全文は `title` と右ドックで読めるようにする。
   - 相手を表示していないときは、上の帯も中身なしで高さだけ残す（「相手を加える」の案内を出す）。相手のON/OFFで盤が動かないようにするため。
   - 周期表の枠 `--pt-h` は**常に確保**する。中身は戦法を選んだときだけ表示し、それ以外のときは薄い案内（「戦法の制約を選ぶと筋ボタンが出ます」）を出す。
     - 行数の上限は3行。もう一方の戦略の行は、枠の中に並べず、ポップオーバーにする。
     - 行の高さは 22px（`--pt-row`）に詰めて、`--pt-h` を約72pxにする。
   - フッタ（凡例・脅威のスイッチ・すべてはずす）は1行で固定する。凡例はアイコンと `title` に縮める。
2. **トーストは盤の上に重ねる**。中央の上端に `position:absolute` で置き、レイアウトに参加させない。
3. **ヘッダは1280px以下でも1行にする**。設定は歯車メニューに畳む（いまは980px以下だけ）。
4. **中央の最小幅を守る**。`grid-template-columns` の中央を `minmax(440px, 1.75fr)` にし、左右のドックの下限を下げる。1180px 以下では右ドックをドロワーにする（計画 §4-6 の未実装分）。
   - 1440×900 の見積もり：900 −54 −32（余白）−56 −72 −56 −24 ≒ 606px の高さに対し、幅は約525px が上限 → 盤は約480px。
   - 1100×800 の見積もり：盤は約400px。
5. **ui-check に不変条件を追加する**。全ステップで `#board` の矩形が変わらない（±0.5px）こと。幅 1440/1280/1100/1024 のそれぞれについて確かめる。

### F3：囲いサムネイル

- 字の実際の大きさは、1440px で 10px、1100px で 8.8px（f6904a4）。
- カードの最小幅（`minmax(60px,1fr)`、`dock.css:106`）に縛られている。
- 方針：
  - 切り出し範囲を「玉・金・銀の外接矩形 ＋ 余白0.5マス」に絞る。
  - カードの最小幅を 84px にして、字を 12px 以上にする。
  - 列が減る分は、ドックが縦にスクロールして吸収する。
  - 共通の倍率で切り出す方式（計画 Q3）は、字が小さくなる原因なので**やめる**。囲いごとに最大化し、大きさの比較は右ドックの盤で行う。

### F4：はみ出し・縦割れ

| 場所 | 原因 | 対応 |
|---|---|---|
| `.sband-sub`（最大320px はみ出す）、見出しの名前が「腰掛\nけ銀」と縦に割れる | wrap と `flex:none` の組み合わせ | 1行に固定して省略（F1 と同時に直す） |
| 戦法タイルの「（既定）」 | `::after` の文字が省略に食われる | 文字ではなく、タイルの角の小さな点線の印にする |

### F5：持ち駒（f6904a4 で左右に置かれた）

- 伝統的な配置に合わせ、後手（相手）は**盤の左上**、先手（自分）は**盤の右下**に寄せる。いまは盤の高さの中央にある。
- 縦書き1列で、2種類以上の駒が並ぶときは「角２」のように枚数の漢数字を添える。
- 持ち駒の列の幅は固定にして、駒の有無で盤が動かないようにする。

## 2. ロジック・将棋の正確さ

### L1：片美濃を選んでも本美濃のまま（dev.md の指摘）

**原因**

- `compose` に状態は無い（前の局面を引き継いでいない）。原因は**合成の土台**にある。
- 振り飛車の戦法の見本配置は、すべて本美濃（金58・金49・銀38・玉28）を含んでいる。
- 合成で守られるのは、戦法の `essential` と囲いの `core` だけ。片美濃の core（玉28 銀38 金49）に含まれない金58 は、そのまま残る。
- 片美濃の `filler` にある「金69」は、合成のときに使われない（`compose.js:209-224`）。
- 影響する組み合わせ：
  - 片美濃：8戦法
  - 木村美濃：7戦法
  - 金無双：銀67 が欠ける
  - 銀矢倉：58金 が欠け、49金 が余る
  - 居飛車の大半：銀26 が 39 になる

**方針：囲いが「守り駒すべて」の置き場所を決める**

- 囲いのデータに `rest` を足す。core に含まれない金・銀（必要なら玉側の桂・香も）を、その囲いでどこに置くかを指定する。
  - 例：片美濃 `rest:'金69'`、木村美濃 `rest:'金69 銀67'`
  - いまの `filler` から金・銀を `rest` へ移す。`filler` は歩・香・桂の比較用の補完だけに戻す。
- 合成の順番は次のとおり。
  1. 戦法の `essential` をロックする
  2. 囲いの `core` を置く
  3. 囲いの `rest` を置く。ロック済みのマスは飛ばす
  4. 戦法のほかの駒
- `rest` に指定が無い金・銀は、**元の位置へ戻す**。金は49/69、銀は39/79 のうち、届くほう。
- `validate` に「合成後の玉・金・銀が、すべて core か rest か essential のマスにある」検査を加える。全組み合わせのスナップショットにも含める。
- 囲いの `hand`（ボナンザ・兜の持ち駒の角）が、戦法と合成すると無視される問題も、この順番の中で扱う。戦法が持ち駒の角を持たない場合に、盤上の角を持ち駒へ移す。

### L2：戦略を変えても連鎖しない（居飛車＋高美濃 が成立する）

- **原因**：`compat.judgeFull` で相性表の `level:'ok'` を処理するとき、`ngAll.length = 0` で **すべての ng を消している**（`compat.js:179-183`）。戦略の不一致（SIDE）まで消える。暗黙値を補う処理（`fillImplied`）も同じ判定を使うので、反対の戦略の戦法・囲いが暗黙値に選ばれる。
- **方針**：相性表の ok で上書きしてよい理由を、データで明示する。
  - 例：`{ castle:'mino', level:'ok', overrides:['SQUARE'], why:'飛車が5五に浮いた形' }`
  - `SIDE` / `KING_ROOK` / `SAME_WING` は、上書きの対象から外す。
  - 戦略層の judge にも同じ規則を適用する。いまは戦略層だけ上書きが効かず、層ごとの判定が食い違っている（L8）。

### L3：居飛車から一段玉・四枚の囲いに組めない

- **原因**：「その駒が動いて届くか」の判定に、アニメーション用のコスト上限 `MAX_COST=4.6` を流用している。銀39 から 79・88 へのコストは 4.9〜5.1 で、上限を超える。
  - 結果として、ミレニアムを選ぶと戦法が「矢倉中飛車」に変わってしまう。
- **方針**：届くかどうかは、`compose` 専用の**手数**で判定する。
  - 駒の動きで何手かかるかを、盤上の障害物を無視して BFS で数える。上限は8手。
  - アニメーションのコストは、どの駒がどの駒に移ったかの対応づけにだけ使う。

### L4：両立しない状態のまま起動する

- **原因**：起動時の正規化（`app.js`）が、重複を除くだけで連鎖による解決をしていない。
- **方針**：起動時の正規化を「リストを先頭から順に `apply(set)` し直す」に変える。旧形式の変換も同じ経路を通す。

## 3. 操作感（UI）

### U1：戦略ボタンが「両方とも赤枠」（dev.md の疑問 → バグ）

- **原因**：相手との相性が◎だと `data-vs="good"` が付き、`box-shadow: inset 0 0 0 1px var(--accent)` が描かれる（`dock.css:70`。`constraint.css:35` にも重複）。
  - 選ばれていないほうのボタンが朱の枠になる。
  - 選択中の印（朱の下線）と、フォーカスの輪（朱 1.5px、`theme.css:48`）も同じ色。
  - 相手が未選択でも、相手面の「振り飛車」に枠が付く。
- **方針**：見た目を役割ごとに分ける。

| 状態 | 見た目 |
|---|---|
| 選択 | 朱の下線と太字。**朱を使うのは選択だけ** |
| 相手との相性 | 文字の◎（相性が良い）／△（相性が悪い）を右肩に。枠は使わない |
| 連動して変わる | `⇄` の印と破線の枠（灰色） |
| フォーカス | 墨色 2px の外側の輪。選択の色と区別する |

- 相手の制約が無いときは、相手との相性の印を一切出さない。

### U2：トーストと元に戻す

- **原因**：「元に戻す」は、トーストを出した時点の状態をクロージャで持っている（`constraint-mode.js:181-196` など3か所）。連鎖が起きない操作ではトーストが更新されないので、古いトーストから複数手前に戻ってしまう。
- **方針**：
  - **元に戻す用の履歴**（`history` に制約リストを最大50件）を store の外のコントローラで持つ。
  - `Ctrl/⌘+Z` で戻し、`Shift+⌘+Z` でやり直す。
  - トーストは操作のたびに必ず置き換えるか閉じる。「元に戻す」は直前の1手だけを戻す。
  - トーストの文言に側を必ず入れる（例：「相手の戦法を…」）。いまは `name` が `'me'` 固定になっている（`:183`）。
  - 外した理由を正しい層に帰属させる。いまは「戦略『振り飛車』を外しました（5八で飛と金が重なる）」のように、戦略の話ではない理由が戦略に付いている。
  - `Esc` でトーストとホバーの予告を閉じる。
  - トーストの表示時間を 4.5秒から 8秒にし、ホバー中は止める。

### U3：キーボード操作

- **原因**：
  - 矢印キーが文書全体のキーとして「選択中の制約の隣へ変更」に割り当てられている（`constraint-mode.js:482-509`）。ドックのタイルにフォーカスしていても制約が変わり、右ドックをキーでスクロールできない。
  - チップを矢印で動かすと、`innerHTML` を作り直すのでフォーカスが失われる（`constraint-bar.js:74`）。
  - Tab で制約チップまで102回かかる。
- **方針**：
  - 矢印キーの役割を、**フォーカスのある部品の中で閉じる**ようにする。
    - ドックの戦法グリッドと囲いのブロック：roving tabindex。矢印でフォーカスを移し、Enter で選ぶ。
    - 制約バー：矢印でチップ間を移り、Delete/Backspace で外す。
    - 盤（中央）にフォーカスがあるときだけ、いまの「隣の戦法・囲いへ送る」を有効にする。
  - 制約バーは差分で更新する。チップを `data-who/kind` で使い回し、フォーカスを保つ。
  - 名前のない `.dk-body[tabindex=0]` に `aria-label` を付ける。Segmented は矢印キーで選べるようにする（radiogroup）。

### U4：「採用中の戦略」と「表示中の戦略」（dev.md の質問への回答と方針）

- **現状の回答**：
  - 状態は「採用中の戦略」1つだけで、表示のための状態は無い。
  - 一覧は常に両方の戦略の項目を出し、反対側の項目を薄く表示しているだけ。
  - 囲いの「薄く表示」は系統単位で判定している。そのため、居飛車のときに本美濃は薄くならず、金無双の系統だけが薄くなる、という食い違いがある。
- **方針**（状態は増やさない）：
  - 各面の一覧を「採用中の戦略の項目」と「もう一方の戦略の項目」の2つに分ける。
  - 後者は折りたたみにし、見出しを「振り飛車の囲い（選ぶと戦略が振り飛車に変わります）」とする。
  - 薄く表示するかどうかは、系統ではなく**項目ごと**に判定する。
- 表示専用の戦略という状態を新しく足す案は、「見えている戦略」と「盤の戦略」が食い違って混乱するので採らない（Q3 で確認）。

### U5：制約チップ

| 問題 | 方針 |
|---|---|
| 選ぶたびにチップの並びが入れ替わる（優先度の順に並べているため） | 表示は**戦略 → 戦法 → 囲いの固定順**にする。優先度は内部だけで持つ |
| 制約が1つだけだと × が出ない | いつでも外せるようにする。外した後は既定値の暗黙チップになり、トーストで「既定の〇〇に戻しました」と伝える |
| 外すと同じ値が暗黙チップとして現れ、「消えない」ように見える | 盤が変わらない場合は、チップを点線に変えるアニメーションで「既定に戻った」ことを示す |
| 導出ラベル（#対抗形）がチップと同じ見た目で、押しても何も起きない | `#` を外し、灰色の文字だけにする。押すと右ドックで戦型の説明を出す |
| チップを選んでも左ドックが連動しない | 選んだチップの側の面を開き、その種類のタブへ切り替えて、項目までスクロールする |

### U6：用語と文言

- UI の語は **自分／相手** に統一する。
  - 先手／後手 は、右ドックの補足として「自分（先手・▲）」の形で1回だけ出す。
  - 「こちら」「対敵」「敵飛車」は使わない。
  - 敵／味方 は dev.md の言い方なので、UI に揃える必要があれば Q1 で決める。
- 内部の語を画面に出さない。
  - 連鎖 → 「連動して変わる」
  - 暗黙 → 「既定」
  - 整合／対敵 → 「相手との相性」
- 名前の出し方を統一する。チップ・タイル・見出しは `short`（短縮名）、右ドックの見出しは正式名。
  - 戦法「居飛車（2筋）」は短縮名が「居飛車」で、戦略の「居飛車」と区別できない。「2筋」に改める。
- 居飛車穴熊のタイルで、注記が二重に出ている（「組むのに手数が…」）。
- 凡例（◎・△・⇄・点線）を、左ドックの上端に `?` ボタンとして置く。

### U7：重複している操作部品

- 「脅威の帯」のスイッチが、左ドックと中央の2か所にある → 中央のフッタだけに残す。
- 両方の面を「自分」にできてしまう問題は、f6904a4 で上が相手専用・下が自分専用になったので解消済みと思われる（再確認）。

### U8：周期表

- 盤の位置との整合は正しい（±0px、相手側の反転も正しい）。
- 「もう一方の戦略の行」は、F1 の方針どおりポップオーバーにする。
- セルは roving tabindex でフォーカスできるようにする。

### U9：ハッシュ

- 旧形式で開いたとき、起動時に新形式で `replaceState` する。
- `hashchange` を購読し、同じタブでアドレスバーを書き換えても反映されるようにする。
- URL に `mw` が無いときは、保存値ではなく既定値（表示する）にする。
