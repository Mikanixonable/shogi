# 改編計画：UI の使いやすさのための内部構造の単純化

UI の使いやすさを上げるため、仕様の変化を許容して内部構造を単純にする。
4画面・制約の優先度リスト＋自動連動・旧形式の移行・2系統の駒アニメなど、
「同じことが複数の経路でできる」「選んでいないものが勝手に変わる」構造を整理する。

## A. 画面の統合

### A-1. 画面を「対局図」1つに統合する
- 現状: 囲い／戦法／対局図／分類マップの4画面がそれぞれ一覧・ステージ・解説を持つ。
  囲い・戦法は対局図の左ドックでも選べ、機能が重複している。解説パネルも重複
  （`RATINGS` が `detail-view.js` と `detail-sections.js` に二重定義）
- 改編: 囲い図鑑・戦法図鑑は「相手なしの対局図で1つ選んだ状態」として扱う。
  ヘッダの画面切替（`#viewSeg`）を廃止する
- 削除: `castle-mode` `tactic-mode` `rail-view` `tactic-rail-view` `tactic-table-view`（周期表）
  `tactic-stage-view` `detail-view` `tactic-detail-view`、state の
  `view / castleId / familyFilter / lastBySide / tacticId / tacticLastBySide / tacticLastByFam`
- 仕様変化: 盤上の周期表は廃止（左ドックの筋タイルが同じ役割を持つ）

### A-2. 分類マップを削除する
- 削除: `cluster-mode` `cluster-model` `cluster-*-view` `clusters.css`、state の `clusterFamily`

## B. 状態モデルの単純化

### B-3. 制約を「各側の固定スロット」に変える
- 現状: `{who,kind,id}[]` の並び順＝優先度で、`dedupe → sides → fillImplied → cascade`
  が他の層を自動で差し替え・削除する（安全網ループあり）。ユーザーには「選んでいないものが変わる」
- 改編: `me: {tactic, castle}` / `opp: {tactic, castle}` の固定スロット。
  両立しない組み合わせは自動では差し替えず、チップに ✕ と理由を出し、直す候補を1クリックで提示する
- 削除: `rank` / `dedupe` / `cascade` / 連動トースト / 解説の「直近の連動」セクション
- 未選択の層は戦法から決まる戦略の既定値で補う（既定の表示は残す）

### B-4. 戦略（居飛車／振り飛車）を制約から外し、戦法から導出する
- 戦法は系統を通じて側が決まるので、戦略は常に「選んだ戦法（無ければ既定戦法）」から導出する
- 左ドックの戦略セグメントは一覧の絞り込み専用にする
- 削除: `strategy` 層、`implied.strategy` の推論、URL の `s` 文字

### B-5. 相手は「表示 ON/OFF」の1スイッチにする
- 現状: 「相手を加える」導線が3か所、`opp:null` の分岐、相手なしで自分の帯が盤上へ回り込む配置替え
- 改編: 相手の状態は常に持ち、OFF のときは描画しない。自分の帯は常に盤の下

### B-6. クリアボタンの整理
- 帯の「相手／自分／すべてをはずす」とドックの「はずす」（計4種）→ ドックの各面に「はずす」1つ。
  全体のリセットは表示設定メニューへ

## C. 永続化と履歴

### C-7. 旧形式の移行コードを削除する
- `matchup` → 制約の変換、旧ハッシュ（`ms/mt/mc…`、`k=` 以前の形式）、`dock.top/bottom` の引き継ぎ
- 仕様変化: 古い保存値・URL は初期状態で開く

### C-8. 盤面状態は URL、表示の好みは localStorage
- 盤面（制約・選択・相手表示）は URL ハッシュを唯一の正とし、変更は `pushState`。
  ブラウザの「戻る」＝元に戻す。`undo.js` を削除
- localStorage は表示の好み（駒の表示・利き・テーマ）だけ
- リセット＝ハッシュを空にする

## D. 表示まわり

### D-9. 表示設定を減らし1つのポップオーバーに
- 駒の表示: 「全駒 / 囲いを強調」の2択（`core` を廃止）
- 守りの利き: ON/OFF のみ（数える範囲 `heatScope` は廃止し囲いの駒に固定）
- 骨格線: 廃止
- 脅威の帯: 左ドックから表示設定へ移す

### D-10. 駒アニメーションを1系統に
- 移動の対応づけ（`piece-match`）を共通の「移動リスト」として1回だけ計算し、
  3D/DOM の各レイヤは描画だけ担う。DOM 版（`?flat`・WebGL なし）はアニメなしの静止表示でよい

### D-11. 左ドックを「自分 / 相手」のタブ切替に
- 分割ペイン・仕切り・面の折りたたみを廃止。削除: `dock-splitter`、`dock.split`、各面の `open`
- 相手表示 OFF のときは「相手」タブを無効化する
- 仕様変化: 両側を同時に見られない（以前のアコーディオン方針から変更）

## 進め方
1. A-2 → C-7（削除のみ）
2. B-5 → B-6 → D-9（UI の重複整理）
3. B-4 → B-3（状態モデル。`tools/unit-test.js`・`expected-matrix.txt` を更新）
4. A-1 → C-8（画面統合）
5. D-10 → D-11

各段階で `node tools/unit-test.js` と `node tools/validate-castles.js` を通す。
README の「画面の構成」と「合成モデルの要点」も最後に合わせて更新する。
