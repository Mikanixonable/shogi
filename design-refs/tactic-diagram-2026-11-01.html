戦法
相手の囲い

いま

  • 囲いのパネルには 特徴の目安（5軸×5段階のペンタグラム） があり、相手がいると戦型の重みを朱の破線で重ねる。
  • 戦法のパネルは #タグ → 説明 → 長所短所 → 主役の駒の動き と文字だけが続き、ひと目で「どういう戦法か」がつかめない。
  • 戦法のデータにあるのは pace（急戦/両用/持久）・lead・route・essential・pairings・against で、囲いの ratings に当たる数値はない。

この資料

  • 上の「戦法」「相手の囲い」を切り替えると、4案すべてが同じ状態で描き直される。
  • A・B は新しい数値データ（仮値）が要る。C・D は既存データだけで描ける（ここでも js/data/tactics.js の実データで描いている）。
  • 戦法の線は主役の駒の系統色（左ドックのタイルと同じ --t-*）、囲いは墨。朱は「効いている・刺さる」印だけに使う。

参考：いまの囲いのペンタグラム

案 A

特徴の目安（戦法独自の5軸）

囲いと同じ形・同じ大きさのペンタグラムを、戦法向けの5軸で描く。派生戦法には親の形を破線で重ね、「何が変わったか」を見せる。

軸（上から時計回り）

攻撃力attack仕掛けたあとの破壊力 速さspeed仕掛けまでの手数。pace から初期値を出せる 柔軟性flex急戦・持久戦や相手の作戦への対応幅 玉の安全safety戦法のために玉形を犠牲にしない度合い 覚えやすさeasy定跡の量・ハメ手への注意の少なさ

良い点

  • 初心者が知りたい問い（強い？速い？難しい？）にそのまま答える。
  • 派生の破線が効く：藤井システムを選ぶと、四間飛車より「速さ↑・玉の安全↓・覚えやすさ↓」が形で分かる。

気になる点

  • 軸が囲いと別物なので、相手の囲いとは重ねられない（相性は従来の文字の節に頼る）。
  • 39戦法すべてに主観の5値が要る。「覚えやすさ」は出典で裏付けにくい。

データ

ratings: { attack, speed, flex, safety, easy } を tactics.js に追加。描画は detail-sections の penta() を軸の表を引数に取る形に広げれば流用できる。

案 B

攻めの向き（囲いの5軸と対になる）

戦法の5軸を、囲いの5軸と同じ位置に「その守りを試す攻め」として置く。相手を表示すると相手の囲いの守りを墨の破線で重ね、攻めが守りを上回る軸を朱で示す。

軸の対応（同じ頂点に置く）

崩す力↔ 堅さ攻めに参加する駒の厚み 押さえ込み↔ 玉の広さ玉の逃げ道を先に消す力 上部攻め↔ 上部の強さ縦（玉頭・筋）から来る攻め 横攻め↔ 横の強さ飛車を成り込んで横から来る攻め 速さ↔ 組みやすさ囲いが組み上がる前に仕掛ける力

良い点

  • 囲い＝守りの形、戦法＝攻めの形、と同じ図法で一対になる。デザイン言語として最も一貫する。
  • 相手表示時に「なぜこの戦法がこの囲いに効くか」が図で読める。既存の対戦相性（matchup.fitness）と同じ考え方で、軸ごとの差をそのまま点数にできる。
  • 囲いのパネルにも逆向きに使える（相手の戦法の攻めを重ねる）。

気になる点

  • 「押さえ込み」は戦法ごとの差が出にくく、評価がぶれやすい。
  • 相手なしのときは A より情報が少なく見える（攻めの向きしか語らない）。

データ

attackProfile: { break, press, top, side, speed }。speed は pace（rapid=4 / both=3 / slow=2）を初期値にし、上書きだけ書く。

案 C

攻めの地図（盤の略図）

囲いのサムネイルが玉と金銀をクローズアップするのと同じ考えで、戦法は「主役の駒・その道筋・狙う筋」だけを濃く描いた略図にする。新しいデータは要らない。

描くもの

  • 主役の駒（lead）を系統色の塗り、必須の駒（essential）を系統色の枠、玉を墨で。ほかの駒は薄く。
  • 道筋（route）を実線の矢印、そこから敵陣三段目までの狙いを朱の破線で。
  • 主役の筋に帯を引き、敵陣（一〜三段目）をうっすら塗る。

良い点

  • 主観の値がゼロ。全39戦法でいますぐ描ける。
  • 「棒銀＝銀が2筋をまっすぐ上がる」という戦法の定義そのものが図になる。マスに乗せると中央の盤で光る連動も既存の data-sq で付く。

気になる点

  • 中央の盤と内容が重なる。モバイルで盤が隠れたときや、相手表示で盤が混んだときに効く図。
  • 「どれくらい強いか」は語らない。ペンタグラムとは役割が違う。
案 D

系統の座標（筋 × 急戦/持久）

同じ系統の戦法を、主役の筋（横）と急戦・持久（縦）の表に置き、いまの戦法がその中のどこにいるかを示す。押すとその戦法に切り替わる。

描くもの

  • 列＝lead.files（盤と同じく9筋が左）、行＝pace。
  • 基本の戦法（basic）は墨の太枠、派生（variantOf）は破線の小さい札。いまの戦法は系統色で塗る。
  • 見本では、上で選べる戦法の札だけ押せる。

良い点

  • 既存データだけ。初心者向けの「基本と派生の見分け」「どれが速いか」をひと目で示せる。
  • 四間飛車 → 藤井システム（同じ6筋で急戦側へ）のように、派生が「どこへずれたか」が位置で分かる。

気になる点

  • 左ドックの「筋ベース」表示と見た目が近く、役割が重なる。
  • pace は3段階しかなく、同じ升に札が積み上がる（居飛車・銀の4筋の急戦は5枚）。
比較

比較と推奨

新しいデータ相手の囲いと重ねる囲いとの一貫性初心者の読みやすさ中央の盤との重複
A 特徴の目安5値×39（主観）できない形は同じ・軸は別高いなし
B 攻めの向き5値×39（主観。速さは pace から）できる（軸が同じ）最も高い相手ありで高いなし
C 攻めの地図不要—サムネイルと同じ考え方高いあり
D 系統の座標不要—低い（独自の表）中左ドックと重複

推奨：B を「囲いのペンタグラム」に当たる主図にし、C を「主役の駒の動き」の節の置き換えにする。

B は囲いと同じ軸なので、ペンタグラムが「守り（囲い）」と「攻め（戦法）」の一対の言語になる。相手を表示したときに右ドックが一番語れるのも B。C は手順の文字列（▲3九銀 → 3八 → …）をそのまま図にしたもので、データを足さずに置き換えられる。A の「覚えやすさ」は B に入らないが、これは左ドックの基本/発展の強調で表す方が筋がよい。D は左ドックの筋ベース表示と重なるので見送り。

未決の点：飛車系の系統色 --t-rook が朱と同じ色なので、振り飛車の戦法では B の「刺さる軸」の朱と多角形が見分けにくい（藤井システム＋美濃で確認できる）。系統色を少しずらすか、刺さる軸の印を色ではなく形（●）で示すかを決める必要がある。

B の値は pace から速さを自動で埋め、残り4軸だけを各戦法に書く。値の無い戦法では B を出さず C だけにすれば、データ整備を段階的に進められる。
