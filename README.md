# 将棋の囲い図鑑

囲い・戦法・戦型を盤面で見比べる静的サイト。自分側と相手側にそれぞれ戦法と囲いを
選ぶと、戦法・囲い（と、戦法から決まる戦略の既定値）を合成した局面が盤に描かれる。
両立しない組み合わせは自動では差し替えず、チップの ✕ と理由で示し、直す候補を
1クリックで選べる。

ビルド工程のない純粋な HTML/CSS/JS で、すべてのデータとロジックはブラウザの
`window.Kakoi` 名前空間に読み込まれる。

## 使い方

`index.html` をブラウザで直接開くか、任意の静的サーバを立てる:

```
npx http-server .
```

GitHub Pages での公開は、このディレクトリ（またはリポジトリルート）を
Pages のソースに指定すれば `index.html` がそのまま配信される。

## 画面の構成

画面は「対局図」の1つだけ（囲い図鑑・戦法図鑑は「相手を出さずに1つ選んだ状態」）。

- **左ドック**: 「自分／相手」のタブで切り替える1枚の面。相手の表示が OFF のときは
  「相手」タブが無効。面は「戦法／囲い」のタブ・「はずす」（見ている側の戦法と囲いを
  両方外す）・戦略（居飛車／振り飛車）の絞り込み・一覧からなる。戦略の絞り込みは
  一覧を絞るだけで、選択の中身は変えない。項目の ✕＋破線枠は「いまの他の層と両立しない」
  印、◎/△ は相手との相性
- **中央ステージ**: 盤の上に相手の帯（状態名・制約バー・表示 ON/OFF スイッチ）、下に
  自分の帯。相手が OFF のときも相手の帯の行は残る（盤の矩形を動かさない）。
  持ち駒は伝統記法で相手=盤左・自分=盤右
- **制約バー**: 各側の「戦法」「囲い」の2チップ（`#名称`）。破線＋「既定」は未選択の層を
  戦略の既定値で補ったもの。他の層と両立しない明示チップには ✕ と理由（title）が付く。
  チップの × でスロットを外す
- **右ドック**: 選択中のスロットの詳細（ペンタグラム・強み弱み・攻め筋・出典）。両立しない
  ときは理由と「代わりの候補」（1クリックで差し替え）が先頭に出る
- **表示設定**（歯車のポップオーバー）: 駒の表示（全駒／囲いを強調）・守りの利き ON/OFF・
  脅威の帯・盤のリセット。表示の好みは localStorage（駒の表示・利き・脅威の帯・左ドックの層・
  テーマ）に保存し、盤面の状態は URL に載せる

### 状態と URL

- 盤面の状態（各側のスロット・相手の表示・選択）は URL ハッシュだけが正:
  `#k=mt:bougin,mc:funa,ot:shikenbisha,oc:mino&opp=1&sel=mc`（`m`/`o`=自分/相手、
  `t`/`c`=戦法/囲い。初期状態は空のハッシュ）。旧形式の URL・保存値は読まず初期状態で開く
- スロットや相手の表示の変更は `pushState` で履歴に積む（ブラウザの「戻る」＝元に戻す。
  選択だけの変更は `replaceState`）。リセット＝ハッシュを空にする
- 駒の移動は `core/piece-match.js` の `plan` が移動リストを1回だけ計算し（`ui/board-view.js`）、
  立体駒レイヤが描く（DOM 駒 `?flat` は静止表示）

## ディレクトリ構成

- `index.html` — アプリのエントリ。`<script>` の列挙は `js/manifest.js` と整合
- `css/` — layout / dock / board / constraint / tactics / matchup / theme
- `js/core/` — DOM 非依存のロジック（`notation` `position` `defaults` `compose` `compat`
  `constraints` `board-model` `matchup` `piece-match` `repository` `validate`）
- `js/data/` — 囲い・戦法・想定配置・出典などのデータ（`castles-*.js` の
  `core/shell/filler/leave/flex` が合成の材料）
- `js/ui/` — 盤描画（`board-view` と駒レイヤ）・左ドック（`dock-*`）・制約バー・
  右ドック（`board-detail-view` `detail-sections`）・`hash-link` などのビュー部品
- `js/modes/` — `constraint-mode.js`（画面の配線とコマンド）・`board-screen.js`（描画）ほか
- `tools/` — 検証スクリプト群（下記）
- `docs/` — 設計・実装計画書

## 検証

```
node tools/unit-test.js          # 合成・両立判定・制約の単体テスト
node tools/validate-castles.js   # 囲い・戦法データのスキーマ検査
node tools/ui-check.js           # ブラウザ巡回の UI チェック（要ブラウザ同梱）
```

`tools/unit-test.js` は `tools/expected-matrix.txt`（戦法×囲いの両立
マトリクスのスナップショット）と照合する。意図した判定変更のときは同
ファイルを消して再生成する。

## 合成モデルの要点

状態（`js/core/constraints.js`）
- 各側は固定スロット `{tactic, castle}`。選んだものを他の層が勝手に差し替えることはない
- 戦略（居飛車／振り飛車）は制約にせず、戦法の系統の側から導く（戦法が無ければ囲いの側、
  どちらも無ければ居飛車）。未選択の層は戦略の既定値（`defaults.js`）で補う
  （既定値が他の層と両立しないときは `compat.searchAlternative` と同じ規則で補う）
- 両立しない明示選択は `conflicts` が理由つきで返し、`suggest` が直す候補を返す
  （どちらも `compat.judge` と同じ判定）。歩同士の接触は相手側の歩を1段下げて避ける（選んだ順は持たない）

局面の合成（`js/core/compose.js`）
- 土台は戦法の局面図、戦法がなければ戦略テンプレート（既定囲い＋想定配置）
- 戦法の essential ∪ 主役（lead）のマスはロックし、囲いは原則それを追い出さない
- `castle.core` → `castle.shell` の順に置く。`filler` は比較専用で置かない
- `castle.leave` で「その囲いではその駒がいない」を宣言できる
  （`金58` = マス指定、filler→初期位置→持ち駒へ退かす。`角` = 盤上全体→持ち駒）
- `castle.flex` で core の目標マスが塞がれたときの崩し形の逃がし先を定義
